# PIXTION

A pixel-art animation studio that runs in the browser. Draw on grids from 8×8 to 512×512,
animate frame by frame, start from 86 templates, and export GIF, video, PNG or sprite sheets.
Installable as an app (PWA) and works offline.

## Project structure

  utilities.css       One-purpose helper classes

js/

  main.js             Entry point: starts every module in order
  shared.js           The shared state object (gallery, profile, undo, stroke)
  state.js            Studio state, drafts, saving (IndexedDB + localStorage)
  core/               Building blocks with no screen of their own

    render.js         Fast pixel drawing and thumbnails
    frames.js         Grid sizes, resize, flip/move, playback order
    palette.js        The 47 colours
    downloads.js      Saving files to the device
    env.js            Detects in-app browsers (Messenger)
  studio/             The drawing workbench
    board.js          Canvas, pointer input, zoom, pan
    tools.js          Pencil, eraser, fill, shapes, spray, dither, replace, mirror
    text-tool.js      Text tool and its pixel font
    history.js        Undo / redo
    frames-ui.js      Frame strip actions, transform, grid size
    palette-ui.js     Palette swatches
    playback.js       Preview, speed, ping-pong, onion skin

    save.js           Save dialog, new art, open saved art
    shortcuts.js      Keyboard shortcuts
    view.js           Frame strip, preview and status rendering
  views/              Screens and dialogs

## Run it locally

ES modules need a web server (opening the file directly will not work):

```
python3 -m http.server 8000     # then open http://localhost:8000
```

## After changing any file

```
node scripts/build.mjs
```

This refreshes the offline file list and its version, so users get the update.

## Protected build (`dist/`)

The `js/` and `index.html` here are the **readable source** — easy to edit and to get help with.
For the version you put online, build the protected copy:

```
npm install            # one time: installs the build tools
npm run build          # creates dist/
```

`dist/` is what you deploy. In it:

- All JavaScript is **bundled into one obfuscated file** (`js/app.min.js`) — it still runs, but it is
  not readable.
- The app's HTML markup is **injected at runtime**, so `view-source:` shows only a small shell, not
  the app. (Open DevTools and the running app is still visible — no website can hide that. This raises
  the effort for a casual snooper; it is a deterrent, not a lock.)
- The **CSS is moved inside the obfuscated bundle** and injected at runtime, so `dist/` has no `.css`
  files at all and the styles never appear in view-source. (The browser still shows computed styles in
  DevTools — that is unavoidable — but there is no readable stylesheet to open.)
- Every JavaScript file is given a **random, content-based name** (e.g. `js/aa3fb22c3407.js`), so the
  filenames carry no hint of what they are and change on every build. The service worker keeps one stable
  name (`pixtion.worker.js`) on purpose — browsers update a worker by its URL.
- Each script carries a **Subresource Integrity** hash, so the browser refuses to run it if a single
  byte was changed in transit (anti-tampering).

Rebuild `dist/` after any change to the source, then redeploy it.

## Deploy to Vercel

```
npm i -g vercel
cd dist           # deploy the protected build
vercel            # first time: log in, framework "Other", accept defaults
vercel --prod
```

Name the project `pixtion` so the address is `pixtion.vercel.app` (the address written in
`index.html`, `robots.txt` and `sitemap.xml`). If you use another address, replace
`pixtion.vercel.app` in those three files.

Do not add a `routes` key to `vercel.json`: it silently turns off all the security headers.

## Security

What protects the app:

- **HTTPS everywhere** (Vercel) plus **HSTS**.
- **Strict Content-Security-Policy**: only files from this site may run, load or style the page.
  No inline scripts, no inline styles, no third-party scripts, fonts or trackers.
- **No embedding** in other sites (`frame-ancestors 'none'`, `X-Frame-Options: DENY`).
- **Cross-origin isolation** (COOP, COEP, CORP) and a locked-down **Permissions-Policy**
  (no camera, microphone, location, payments).
- **Input validation** (`js/core/sanitize.js`): backups, saved data and typed names are checked
  and cleaned before use; unknown fields are dropped; file sizes are limited.
- **All text is escaped** before it is shown, so a malicious title cannot run code.
- **No server and no accounts**: art stays in the user's own browser, so there is no database
  or API to break into.

- **Obfuscated, shell-only `dist/`**: the deployed code is unreadable and `view-source:` shows only a
  stub, so the app's structure is not handed over in plain text.
- **Subresource Integrity**: the browser runs the scripts only if their bytes are untampered.

What it cannot do (true for every website): code that runs in a browser is always visible to
that browser. `js/guard.js` blocks right-click and developer-tool shortcuts to discourage casual
poking, but anyone determined can still read the code. That is fine here because the app holds no
secrets.
